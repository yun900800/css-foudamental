# 01-011.html Grid 布局疑问解析（续）—— 布局算法优先

## 一句话结论

> **Grid 布局算法先算列宽 → 再往下传递 → 图片 `width: 100%` 只是跟随者，不是决定者。**

---

## 1. 执行顺序

```
                 ① Grid 布局算法（auto-fill + minmax）
            优先       ↓
         ═══════▶  ② grid item (li) 宽度 = 列宽
                        ↓
                    ③ a { display: block } 填满 li
                        ↓
                    ④ img { width: 100% }  →  "父容器多宽我就多宽"
```

**Grid 是"甲方"**，它先根据容器宽度算好列数、列宽，然后把每个 grid item 放到对应的轨道里。

**图片的 `width: 100%` 是"乙方"**，它只是被动地"父容器给我多大空间我就占多大"，没有任何谈判权。

---

## 2. 为什么 500px 原始宽无效？

```
500px 原始宽 = intrinsic size（内在尺寸 / 自然尺寸）
width: 100%  = 显式 CSS 声明 → 优先级高于内在尺寸
```

CSS 规范中，**显式声明的 `width` 优先级永远高于图片的内在尺寸**。

| 规则 | 优先级 |
|:----:|:------:|
| 图片 intrinsic size（500px） | ❌ 最低 |
| `width: 100%`（相对父容器） | ✅ 高 |
| Grid 列宽（决定父容器宽度） | ✅ ✅ **最高（优先计算）** |

---

## 3. 换个角度看：给图片设固定宽度会怎样？

假设你在 Grid 里强行给图片设固定宽：

```css
.index img {
  width: 500px;   /* 强行 500px */
}
```

结果会怎样？**图片会溢出！** 因为：

```
Grid 列宽 = 195px
img width: 500px → 超出 li（grid item）的范围
```

```
┌─────────────┐  ← Grid 列宽 195px
│ ┌─────────────────┐
│ │  图片 500px ▶▶▶▶▶▶▶ 溢出!
│ └─────────────────┘
└─────────────┘
```

这也反过来证明：**Grid 先定宽度 → 图片再适配，而不是反过来**。

---

## 4. 类比理解

| 角色 | 类比 | 说明 |
|:----:|:----:|:----:|
| Grid 布局算法 | 🏗️ **建筑师** | 先设计房间（列）的大小和数量 |
| `width: 100%` | 🪑 **租客** | 房间多大，家具就摆多大 |
| 图片 500px | 📦 **搬家前的大箱子** | 原始尺寸再大，进了小房间也得缩 |
| `max-width: 300px` | 🚪 **房间门宽** | 如果房间大于门宽才限制，否则不触发 |

---

## 5. 验证方法

打开浏览器 DevTools → Elements，选中一个 `<li>`（grid item）：

```
Computed 面板：
  width: 195px   ← Grid 给的列宽
  max-width: 300px (仍然存在，但未生效，因为 195 < 300)
```

再选中 `<img>`：

```
Computed 面板：
  width: 195px   ← 父容器 li 的宽度
  intrinsic: 500px × 333px (原始尺寸，被压缩显示)
```

两者一致——图片宽度 = li 宽度 = Grid 列宽。

---

## 6. 总结

> **Grid 先算好布局（列数、列宽），然后才轮到图片去适配这个宽度。**
>
> 执行链条不可逆：
> ```
> Grid 布局算法 → 列宽 → li → a → img { width: 100% }
> ```
>
> 图片的 500px 原始宽只是一个"出生证明"，`width: 100%` 让它在 Grid 的"地盘"上乖乖听指挥。
