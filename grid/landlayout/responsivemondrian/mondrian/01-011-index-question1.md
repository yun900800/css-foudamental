# 01-011.html Grid 布局疑问解析

## 问题

在 `01-011.html` 中，图片原始宽度为 **500px**，但在以下 CSS Grid 布局下，图片被压缩到约 **218px**：

```css
@supports (display: grid) {
  .index ul {
    display: grid;
    grid-template-columns: repeat(auto-fill, minmax(180px, 1fr));
    grid-gap: 2rem;
    width: auto;
  }
  .index li {
    width: auto;
    margin: 0;
  }
}
```

Grid 是如何控制列数，又是如何把图片压缩的？

---

## 1. 为什么 500px 的图片会被压缩？

### 关键样式链

```css
/* 第 1 层：非 Grid 兜底样式 */
.index li {
  max-width: 300px;         /* 普通布局下 li 最大 300px */
}
.index img {
  width: 100%;              /* 图片宽度 = 父容器宽度的 100% */
}

/* 第 2 层：Grid 启用后覆盖 li 限制 */
@supports (display: grid) {
  .index li {
    width: auto;            /* 移除 max-width:300px 限制 */
    margin: 0;
  }
}
```

### 宽度传递链

```
Grid 列宽  →  <li> (grid item)  →  <a> (display: block)  →  <img> (width: 100%)
```

> **图片的 500px 只是 intrinsic size（内在尺寸）。**  
> `width: 100%` 使图片宽度**始终等于父容器宽度**，而非原始尺寸。  
> 浏览器的行为是：**先按 100% 的约束渲染，再等比缩放高度保持宽高比**。

---

## 2. Grid 如何决定列数？

### 核心属性拆解

```css
grid-template-columns: repeat(auto-fill, minmax(180px, 1fr));
```

| 部分 | 含义 |
|------|------|
| `auto-fill` | 在容器宽度内，尽可能多地创建列轨道 |
| `minmax(180px, 1fr)` | 每列宽度在 **180px ~ 1fr** 之间 |
| `180px` | **下限** — 列不能窄于 180px |
| `1fr` | **上限** — 如果空间有余，均分剩余空间 |
| `grid-gap: 2rem` | 列间距（默认 1rem = 16px，故 2rem = **32px**） |

### 算法步骤

以 **1200px** 视口为例：

#### Step 1 — 计算容器可用宽度

```
视口宽度:                    1200px
.index main margin: 3rem × 2 = 96px
容器 (.index ul) 可用宽度:   1200 - 96 = 1104px
```

#### Step 2 — 计算最多能容纳几列

> **公式：`N × 180 + (N - 1) × 32 ≤ 可用宽度`**

| N（列数） | 列占宽 | 间距占宽 | 合计 | 是否不超过 1104px |
|-----------|--------|---------|------|:----------------:|
| 5 | 900px | 128px | **1028px** | ✅ |
| 6 | 1080px | 160px | **1240px** | ❌ 超了 |

→ 最大能放 **5 列**。`auto-fill` 即创建 **5 列**。

#### Step 3 — 确定每列实际宽度（`1fr` 分配）

```
剩余空间 = 1104 - 5 × 32 = 1104 - 128 = 976px
每列宽度 = 976 ÷ 5 = 195.2px
```

> 图片最终被约束到 **~195px** 宽。

---

## 3. 不同视口下的列数与列宽

| 视口宽度 | 容器宽度 | 可容纳列数 | 每列实际宽度 | 近似值 |
|---------|---------|:----------:|:-----------:|:-----:|
| 800px | 704px | 3 | (704 - 64) ÷ 3 | **~213px** |
| 900px | 804px | 3 | (804 - 64) ÷ 3 | **~247px** |
| 1000px | 904px | 4 | (904 - 96) ÷ 4 | **~202px** |
| 1070px | 974px | 4 | (974 - 96) ÷ 4 | **~220px ← 你的 218px** |
| 1200px | 1104px | 5 | (1104 - 128) ÷ 5 | **~195px** |
| 1400px | 1304px | 6 | (1304 - 160) ÷ 6 | **~191px** |
| 1500px | 1404px | 6 | (1404 - 160) ÷ 6 | **~207px** |
| 1675px | 1579px | 7 | (1579 - 192) ÷ 7 | **~198px** |

> **218px 的来源**：当视口约 **1070px** 时，容器宽 974px，恰好放下 4 列，每列约 219.5px，取整 ≈ **218px**，与你的观察吻合 ✅

---

## 4. 核心结论

```
minmax(180px, 1fr)     ← 设定了每列的下限为 180px
       ↓
  repeat(auto-fill, …) ← 在容器宽度内尽量多塞列
       ↓
         1fr           ← 把剩余空间均分给各列
       ↓
     列宽确定          ← 这个宽度通过「li → a → img」链传递
       ↓
   img { width: 100% } ← 图片被压缩到列宽
```

- **500px 原始宽 → 218px 显示宽**：不是 Grid 直接设置图片宽，而是 `width: 100%` 让图片填满 grid 列宽
- **列数自动变化**：`auto-fill` + `minmax(180px, ...)` 决定了「能放几列放几列」
- **每列最少 180px** 保证了窄屏不会把列挤得太小

---

## 5. 附：`auto-fill` vs `auto-fit`

```css
/* auto-fill  — 保留空列轨道 */
repeat(auto-fill, minmax(180px, 1fr))

/* auto-fit  — 折叠空列，有内容的列撑满 */
repeat(auto-fit, minmax(180px, 1fr))
```

| 特性 | `auto-fill` | `auto-fit` |
|------|:-----------:|:----------:|
| 空列是否占位 | ✅ 是 | ❌ 否，被折叠 |
| 6 个项目能放 6 列时 | 表现一样 | 表现一样 |
| 3 个项目能放 6 列时 | 保留 6 列，后 3 列空 | 折叠空列，3 个项目瓜分全部空间 |

本例中 6 个 `<li>`，在大多数视口下恰好与最大列数接近，两者差异不明显。你可以改为 `auto-fit` 观察细微差别。
