# 01-003D.html 五种 CSS Grid `<ul>` 布局分析

> 页面标题："A 5-part Demo of CSS Grid"
> 这是一个展示 CSS Grid 五种不同布局策略的演示项目。
> 当前 `01-003D.html` 包含 `explicitly-placed` 节，CSS 文件 `01-003.css` 完整定义了全部 5 种模式。

它们共享一套基准样式（`ul` 通用规则：去列表符号、内边距、背景色、阴影），再各自通过类名叠加不同的 Grid 规则。

---

## 1️⃣ `.fixed ul` — 固定尺寸布局

```css
.fixed ul {
  display: grid;
  grid-template-columns: repeat(4, 100px);  /* 4列，每列固定100px */
  grid-gap: 4px;
  width: calc(400px + 12px + 4.4rem);
}

@media (max-width: 660px) { .fixed ul { grid-template-columns: repeat(3, 100px); ... } }
@media (max-width: 490px) { .fixed ul { grid-template-columns: repeat(2, 100px); ... } }
@media (max-width: 320px) { .fixed ul { grid-template-columns: repeat(1, 100px); ... } }
```

### 作用
每列宽度**固定为 `100px`**，不受容器大小影响。通过媒体查询在屏幕变窄时**减少列数**（4列 → 3列 → 2列 → 1列），而不是缩小列宽。

### 如何体现意图

| 手法 | 意图 |
|------|------|
| `repeat(4, 100px)` | 每列固定 100px，内容尺寸可控，适合缩略图等需要保持最小可读尺寸的场景 |
| 多层 `@media` 断点递减列数 | 当容器放不下时**丢弃列**而非压缩列宽，保证每个格子内容不扭曲变形 |
| `width: calc(...)` | 手动计算总宽度 = 列宽总和 + gap总和 + padding，精确控制容器尺寸 |

**典型场景**：图片画廊、图标网格——每个条目有最小可接受尺寸，宁可减少数量也不压缩质量。

---

## 2️⃣ `.fluid ul` — 流式布局（弹性比例）

```css
.fluid ul {
  display: grid;
  grid-template-columns: repeat(5, 1fr);  /* 5列，每列等分可用空间 */
  grid-gap: 0.25rem;
  max-width: 100%;
}
```

### 作用
使用 `1fr` 弹性单位，**5 列平分容器全部可用宽度**。容器变宽则每列变宽，容器变窄则每列变窄，始终填满 100%。

### 如何体现意图

| 手法 | 意图 |
|------|------|
| `repeat(5, 1fr)` | 所有列**等比例分配空间**，充满容器宽度，无固定尺寸 |
| `max-width: 100%` | 始终撑满父容器，不会溢出 |
| **无媒体查询** | 完全依赖浏览器自动分配，纯流体行为 |

**典型场景**：仪表盘面板、等分导航栏——希望内容始终均匀充满屏幕，不关心每列绝对尺寸。

---

## 3️⃣ `.responsive ul` — 响应式布局（自动填充）

```css
.responsive ul {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(120px, 1fr));
  grid-gap: 0.25rem;
}
```

### 作用
**自动决定列数**：每列最小 `120px`，最大 `1fr`（弹性拉伸）。容器越宽，列数越多；容器变窄到放不下 120px 时，自动减少列数。

### 如何体现意图

| 手法 | 意图 |
|------|------|
| `auto-fit` | 自动计算能放下多少列，多余的轨道折叠掉 |
| `minmax(120px, 1fr)` | 列宽下限 120px（保证最小可读性），上限 1fr（有空间就拉伸填充） |
| **无需任何媒体查询** | 纯 CSS Grid 自身响应，容器宽窄自动适配列数 |

**对比**：
- **vs `.fixed ul`**：fixed 是媒体查询手动控列数，responsive 是 Grid 自动算。
- **vs `.fluid ul`**：fluid 列数固定（5列），responsive 列数可变。

**典型场景**：卡片列表、商品展示——条目数量不确定，希望自动换行且保持最低宽度。

---

## 4️⃣ `.explicitly-placed ul` — 显式定位布局

```css
.explicitly-placed ul {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  max-width: 600px;
}

/* 每个 li 手动指定行列位置 */
.explicitly-placed li:nth-child(1) { grid-column: 2 / 3;  grid-row: 1 / 2; }
.explicitly-placed li:nth-child(2) { grid-column: 4 / 5;  grid-row: 2 / 3; }
.explicitly-placed li:nth-child(3) { grid-column: 3 / 4;  grid-row: 3 / 4; }
.explicitly-placed li:nth-child(4) { grid-column: 1 / 2;  grid-row: 5 / 6; }
.explicitly-placed li:nth-child(5) { grid-column: 4 / 5;  grid-row: 5 / 6; }
```

### 作用
**手动指定**每个 `<li>` 放在网格的哪个单元格——不按 DOM 顺序自动排列，而是精确控制每个条目的位置。

### 如何体现意图

| 手法 | 意图 |
|------|------|
| `grid-column` / `grid-row` 逐一定位 | 每个子项**完全脱离文档流顺序**，放到设计师指定的格子 |
| 位置是跳跃的（列 2→4→3→1→4） | 刻意制造非连续、非顺序的视觉节奏，展示 Grid 的自由度 |
| 行号也跳跃（行 1→2→3→5→5） | 中间可留空行，网格线编号直接控制布局 |

**典型场景**：杂志排版、海报式布局、不规则拼贴——需要将条目放在特定视觉位置，而非简单流式排列。

---

## 5️⃣ `.overlapping ul` — 重叠布局

```css
.overlapping ul {
  display: grid;
  grid-template-columns: 4fr 2fr 2fr 3fr 6fr;  /* 5列不等宽 */
  max-width: 600px;
}

.overlapping li:nth-child(1) {
  grid-row: 1 / span 2;     /* 占2行 */
  grid-column: 1 / span 2;   /* 占2列 */
  z-index: 2;                /* 叠在上层 */
}

.overlapping li:nth-child(2) {
  grid-row: 2 / span 4;     /* 占4行 */
  grid-column: 2 / span 3;   /* 占3列 */
  /* 无 z-index，默认 0 */
}

.overlapping li:nth-child(3) {
  grid-row: 4 / span 3;
  grid-column: 4 / span 2;
  z-index: 2;               /* 叠在上层 */
}
```

### 作用
利用 Grid 允许**单元格重叠**的特性——多个 `<li>` 占据同一片网格区域，配合 `z-index` 控制谁在上层，形成图片叠压的视觉效果。

### 如何体现意图

| 手法 | 意图 |
|------|------|
| `span 2` / `span 4` 跨多行列 | 每个条目占据不同大小的区域，打破均匀网格 |
| li(1) 占 row 1-2 / col 1-2，li(2) 占 row 2-5 / col 2-4 | 两者在 **row 2 / col 2** 处**重叠** |
| `z-index: 2`（li 1 & 3） vs 默认 0（li 2） | 控制叠放顺序，li(1) 和 li(3) 浮在 li(2) 之上 |
| 不等宽 `4fr 2fr 2fr 3fr 6fr` | 每列比例不同，让重叠区域大小更有层次 |

**典型场景**：拼贴画、艺术性照片墙、杂志封面——需要元素部分层叠，形成纵深感和视觉趣味。

## 总结对比

| 类型 | 列宽策略 | 列数 | 位置控制 | 响应式手段 | 核心意图 |
|------|---------|------|---------|-----------|---------|
| **fixed** | `100px` 固定 | 随断点减少 | 自动排列 | 媒体查询 | 保持内容最小可读尺寸 |
| **fluid** | `1fr` 弹性 | 固定 5 列 | 自动排列 | 无（纯弹性） | 始终填满容器，均匀分布 |
| **responsive** | `minmax(120px, 1fr)` | 自动计算 | 自动排列 | Grid 自动换行 | 兼顾最小宽度和空间利用率 |
| **explicitly-placed** | `1fr` 弹性 | 固定 4 列 | **手动指定** | 无 | 自由控制每个元素位置 |
| **overlapping** | 不等比 `fr` | 固定 5 列 | **手动 + 重叠** | 无 | 元素叠压创造层次感 |

这 5 种布局形成了一个从**"完全自动"到"完全手动"**的光谱：

- **自动端**：fluid → responsive → fixed（按弹性/固定+响应程度）
- **手动端**：explicitly-placed → overlapping（按是否重叠）

CSS 通过 `grid-template-columns` 的组合（固定值 `100px` / 弹性值 `1fr` / `minmax` / 混合比例 `4fr 2fr...`）、`auto-fit` 关键字、显式 `grid-column/row` 以及 `z-index` 这几组手段，清晰地表达了每种布局策略的设计意图。

## 综合对比：优势 · 劣势 · 使用场景 · 关键属性

### 1️⃣ `.fixed ul` — 固定尺寸布局

| 维度 | 说明 |
|------|------|
| **优势** | ① 每列尺寸**完全可预测**，设计师能精确知道每个条目多大；② 内容永不扭曲变形，图片始终保持原始宽高比；③ 适合精确的栅格系统（如 100px 基准的 4-3-2-1 列切换） |
| **劣势** | ① 必须手写**多个媒体查询**，维护成本高；② 大屏上有大量**留白**浪费空间（4×100px 才 400px 宽，大屏幕两侧全空）；③ 内容数量固定，无法自适应扩展 |
| **适用场景** | 相册缩略图、图标工具栏、emoji 选择器、需要精确对齐的设计稿还原——任何**条目有硬性最小尺寸**且不介意留白的地方 |
| **响应式方式** | ✅ 需要媒体查询（手动管理断点） |
| **留白能力** | ✅ 可以（固定宽 + 容器更宽 = 自然留白） |
| **关键 Grid 属性** | `grid-template-columns: repeat(N, 固定值)` — 固定轨道 |

---

### 2️⃣ `.fluid ul` — 流式布局（弹性比例）

| 维度 | 说明 |
|------|------|
| **优势** | ① **无需任何媒体查询**即实现响应式，代码极简；② 始终**填满容器**，空间利用率 100%；③ 所有列严格等宽，视觉整齐划一 |
| **劣势** | ① 列数**固定不变**，窄屏时每列被压缩到极小，可能导致内容难以阅读；② 列宽由容器决定，无法保证每列内容的最小可读尺寸；③ 大屏上每列可能过宽，行太长影响阅读体验 |
| **适用场景** | 仪表盘面板、等分导航/工具栏、图表网格、统计卡片——**列数固定不重要，内容弹性可缩放**的场景 |
| **响应式方式** | ❌ 不需要（纯 fr 弹性，但窄屏可能出问题，可配合 `minmax` 改良） |
| **留白能力** | ❌ 不会（始终撑满，不留白） |
| **关键 Grid 属性** | `grid-template-columns: repeat(N, 1fr)` — 等分弹性轨道 |

---

### 3️⃣ `.responsive ul` — 响应式布局（自动填充）

| 维度 | 说明 |
|------|------|
| **优势** | ① **无需媒体查询**即自动响应，`auto-fit` + `minmax` 自动算列数；② **兼顾弹性与底线**——列宽在 120px~1fr 之间浮动，既不太窄也不太空；③ 空间利用率极高，大屏多列、小屏少列，自动适配 |
| **劣势** | ① 当条目数量少时，`auto-fit` 会把剩余空间全部分配给已有列，导致列宽异常大（可用 `auto-fill` 替代解决）；② 无法精确控制每行展示几个条目（列数由容器宽度和 minmax 共同决定）；③ 极端窄屏下如果 `minmax` 下限太高，可能单列也放不下 |
| **适用场景** | **最通用的推荐方案**——商品列表、卡片网格、文章列表、文件管理器——条目数量动态变化，希望自动换行且每项有合理最小宽度的绝大多数场景 |
| **响应式方式** | ❌ 不需要（Grid 自动根据容器宽度调节列数） |
| **留白能力** | ⚠️ 有限（`auto-fit` 会拉伸填充，`auto-fill` 会保留空白轨道） |
| **关键 Grid 属性** | `grid-template-columns: repeat(auto-fit/auto-fill, minmax(最小宽, 1fr))` — 自动填充 + 弹性下限 |

> 💡 **`auto-fit` vs `auto-fill` 的区别**：
> - `auto-fit`：空轨道折叠掉，已有列拉伸填满（不留白）
> - `auto-fill`：保留空轨道（留白），适合条目少时不自适应撑大

---

### 4️⃣ `.explicitly-placed ul` — 显式定位布局

| 维度 | 说明 |
|------|------|
| **优势** | ① **完全控制**每个条目的位置，实现非规则、非顺序的创意布局；② 可以自由跳过网格中的某些单元格，制造**留白/空档**；③ 视觉节奏丰富，适合艺术性、杂志风格 |
| **劣势** | ① 每个子项都要手写 `grid-column` / `grid-row`，**维护成本极高**；② 新增/删除条目需要重新调整所有定位，**可扩展性差**；③ **响应式困难**——窄屏下需要重写所有定位规则，工作量翻倍；④ DOM 顺序和视觉顺序不一致，影响键盘导航和屏幕阅读器 |
| **适用场景** | 杂志排版、海报式首页、作品集展示、营销活动页——**内容固定、设计驱动、追求视觉效果**的场景 |
| **响应式方式** | ⚠️ 需要额外工作（通常得配合媒体查询重新定位） |
| **留白能力** | ✅ 可以（条目不连续放置 = 自然产生空白单元格） |
| **关键 Grid 属性** | `grid-column: 起始线 / 结束线` — 显式指定水平位置<br>`grid-row: 起始线 / 结束线` — 显式指定垂直位置 |

---

### 5️⃣ `.overlapping ul` — 重叠布局

| 维度 | 说明 |
|------|------|
| **优势** | ① 创造普通流式布局无法实现的**层次感和纵深**；② 视觉冲击力强，适合吸引注意力；③ 利用 `z-index` 控制前后关系，设计自由度极高 |
| **劣势** | ① 可读性和可访问性差——文字可能被遮挡；② **响应式极难**——重叠区域在小屏上会严重冲突；③ 需要精心计算每项跨几行几列才能重叠出预期效果，调试成本高；④ 不适合内容动态变化的场景 |
| **适用场景** | 艺术性封面页、品牌展示页、游戏界面、创意着陆页——**追求视觉冲击 > 追求实用性和可访问性**的场景 |
| **响应式方式** | ⚠️ 困难（通常需要完全重构布局） |
| **留白能力** | ⚠️ 通过行列不等宽 + 重叠自然产生负空间效果 |
| **关键 Grid 属性** | `grid-column: 起始线 / span N` — 跨多列<br>`grid-row: 起始线 / span N` — 跨多行<br>`z-index: N` — 控制叠层顺序 |

## 🧭 选型决策指南

```
你关心每列有最小可读尺寸吗？
├─ 是 → 你能接受写媒体查询吗？
│   ├─ 是 → fixed（固定列宽 + 断点减列）
│   └─ 否 → responsive（auto-fit + minmax）
│
└─ 否 → 你希望列数固定还是自动？
    ├─ 固定 → fluid（repeat + 1fr）
    └─ 自动 → responsive（auto-fit + minmax）

你是做创意/艺术性布局吗？
├─ 是 → 你需要元素重叠吗？
│   ├─ 是 → overlapping
│   └─ 否 → explicitly-placed
└─ 否 → 从上面三选一（推荐 responsive 作为默认首选）
```

## 🔑 核心 Grid 属性速查表

| 属性 | 作用 | 用于哪些模式 |
|------|------|-------------|
| `display: grid` | 开启 Grid 容器 | 全部 5 种 |
| `grid-template-columns` | 定义列轨道（尺寸+数量） | 全部 5 种 |
| `repeat(N, 尺寸)` | 重复 N 次相同尺寸的轨道 | fixed, fluid, explicitly-placed |
| `repeat(auto-fit, ...)` | 自动填充，折叠空轨道 | responsive |
| `repeat(auto-fill, ...)` | 自动填充，保留空轨道（留白） | responsive 变体 |
| `minmax(min, max)` | 轨道尺寸在最小~最大之间弹性变化 | responsive |
| `1fr` | 弹性单位，剩余空间按比例分配 | fluid, responsive, explicitly-placed, overlapping |
| `grid-gap` / `gap` | 网格间距 | fixed, fluid, responsive |
| `grid-column` | 指定子项的水平起始/结束位置 | explicitly-placed, overlapping |
| `grid-row` | 指定子项的垂直起始/结束位置 | explicitly-placed, overlapping |
| `span N` | 跨 N 条轨道 | overlapping |
| `z-index` | 控制重叠元素的层叠顺序 | overlapping |
| `@media` | 媒体查询，手动切换断点布局 | fixed（必要）, overlapping（可选） |
